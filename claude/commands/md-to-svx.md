# Markdown to SVX Converter

Convert Obsidian vault blog posts (`.md`) into mdsvex-compatible `.svx` files for the hacker1db.dev SvelteKit blog.

Before converting, read `$HOME/.config/blog/hacker1db-voice.md` for the SVX frontmatter schema and blog repo layout.

## Arguments

- `$ARGUMENTS` — the name (or partial name) of the blog post in the vault. If omitted, list available posts and ask which one to convert.

## Conversion Steps

### 1. Locate the Source File

Search for the post in `$HOME/notes/SecondBrain/2.Areas/Personal Home/Blog Posts 🕸/`. Match by partial filename if a full name isn't given. If multiple matches, ask the user to pick one. Read the full file.

### 2. Find the Blog Repo Worktree

The blog repo at `$HOME/Developer/side-code/web-hacker1db/` uses a bare repo with worktrees. Find the active SvelteKit worktree by looking for the directory containing `svelte.config.js`:

```bash
find "$HOME/Developer/side-code/web-hacker1db" -maxdepth 2 -name "svelte.config.js" -not -path "*node_modules*" | head -1
```

The content directory is `{worktree}/content/posts/{Category}/`.

### 3. Transform Frontmatter

Map Obsidian frontmatter to the SVX schema defined in the shared reference:

| Obsidian field | SVX field | Notes |
|---|---|---|
| `title` | `title` | Keep as-is, wrap in quotes |
| `date` | `date` | ISO format, no quotes: `YYYY-MM-DD` |
| `author` | `author` | Always `hacker1db` (no quotes) |
| `description` | `subtitle` | Use description as subtitle |
| `tags` | `tags` | Convert to YAML list format (one item per line with `  - "tag"`) |
| `categories` | `series` | Map to series array; use `[]` if no clear series |
| `draft` | `draft` | Keep as-is |
| — | `thumbnail` | Search Unsplash for a relevant photo (WebSearch `site:unsplash.com [topic]`), construct `https://images.unsplash.com/photo-{id}?w=1200`, add `<!-- Photo by [Name] on Unsplash -->` after closing `---` |
| — | `youtube` | Add `youtube: ""` (empty unless there's an associated video) |
| — | `toc` | Add `toc: true` by default |

**Remove** Obsidian-only fields: `aliases`, `cssclass`, `cssclasses`, `publish`, `featured`, `permalink`, `uid`.

If frontmatter is missing, construct it by inferring title from the first `# heading` and asking the user for category/tags.

If the post was generated by a blog-draft agent and already uses the SVX schema, only add `thumbnail` (via Unsplash search) and `youtube: ""` if missing.

### 4. Convert Obsidian-Specific Syntax

**Wikilinks**:
- `[[Page Name]]` → `Page Name` (plain text — vault links don't map to blog routes)
- `[[Page Name|Display Text]]` → `Display Text`
- `[[Page Name#Heading]]` → `Page Name > Heading`

**Embeds**:
- `![[embedded-note]]` → remove (warn user that embedded content was stripped)
- `![[image.png]]` → `![image](/images/posts/image.png)` (remind user to copy image to `{worktree}/static/images/posts/`)

**Callouts** → styled blockquotes:
- `> [!note] Title` → `> **Note:** Title`
- `> [!warning] Title` → `> **Warning:** Title`
- `> [!tip] Title` → `> **Tip:** Title`

**Obsidian comments** — Remove `%%comment%%` blocks.

**Dataview/templater** — Strip any `dataview` or `templater` code blocks or inline queries.

**HTML comments** — Preserve `<!-- Research Sources: ... -->` blocks (these are source attribution from blog-researcher).

### 5. Determine Output Category

Pick the category directory based on `series` (or `categories`) frontmatter. Directory names from the shared reference:
- Security/CyberSecurity/InfoSec/DevSecOps → `CyberSecurity/`
- DevOps/Infrastructure/Docker/Kubernetes → `DevOps/`
- Programming/Development/Code → `Programing/` (note existing spelling)
- Testing/QA → `Testing/`
- If unclear, ask the user.

### 6. Generate the Filename

Kebab-case slug from the title:
- Lowercase, replace spaces and special characters with hyphens
- Remove consecutive hyphens, strip leading/trailing hyphens
- Example: `"Security for Developers: Essential Knowledge"` → `security-for-developers-essential-knowledge.svx`

### 7. Write the .svx File

Write to `{worktree}/content/posts/{Category}/{slug}.svx`. Show the user:
- Source path
- Destination path
- Summary of transformations (frontmatter changes, syntax conversions, warnings)

### 8. Post-Conversion Checklist

Remind the user about anything needing manual attention:
- Images that need copying to `{worktree}/static/images/posts/`
- Embedded notes that were stripped
- Links that pointed to other vault notes
- Whether `draft: true` should be changed to `false`

## Publish Mode

If the user says "publish" or passes `--publish`, also:
1. Set `draft: false` in the .svx frontmatter
2. After writing, show the `git diff --stat` in the blog repo worktree so the user can review before committing

## Batch Mode

If the user asks to convert multiple posts or "all posts", iterate through the vault blog directory. Skip files that:
- Have no frontmatter (stubs or link collections)
- Already exist in the svx output directory (warn and ask whether to overwrite)

Show a summary table: filename, category, status (converted/skipped/error).

## Example

**Input** (Obsidian `.md`):
```markdown
---
title: "My Post Title"
date: "2025-09-28"
author: "hacker1db"
subtitle: "A post about security"
tags: ["security", "devops"]
series: ["Security"]
toc: true
draft: false
---

# My Post Title

Check out [[Other Note]] for more info.

> [!tip] Pro tip
> Always validate input.
```

**Output** (`.svx` — identical if frontmatter already matches schema):
```markdown
---
title: "My Post Title"
date: "2025-09-28"
author: "hacker1db"
subtitle: "A post about security"
tags: ["security", "devops"]
series: ["Security"]
toc: true
draft: false
---

# My Post Title

Check out Other Note for more info.

> **Tip:** Pro tip
> Always validate input.
```
