# CI and security scanning

`.github/workflows/ci.yml` runs on pushes to `main` and on pull requests: `zsh -n` over `install.sh`, `install/*.zsh`, the Zsh configuration, and every Zsh script in `bin/` and the Git hooks; ShellCheck at warning severity over the Bash and POSIX shell scripts in `bin/`, the Git hooks, and the SketchyBar plugins; `ruby -c` over `bin/gbrt`; plus Luacheck over the Neovim config (ignoring existing unused-variable and line-length warnings). A `secrets` job runs the GitGuardian `ggshield` action, pinned to a commit SHA, over the commits a pull request adds (base to head) or a push adds (before to after), not the full history, and fails on any detected secret. Add a GitGuardian API key with scan scope as `GITGUARDIAN_API_KEY` in both the repository Actions secrets and the Dependabot secrets, so scans can authenticate for regular and Dependabot pull requests. Same-repository pull requests, including Dependabot pull requests, use the `pull_request` event; Dependabot gets the key from Dependabot secrets. Fork pull requests get no secrets, so their `secrets` check fails closed with an explicit error until a maintainer scans the changes; the workflow deliberately avoids `pull_request_target`, which would hand the key to a job reading fork-controlled `.gitguardian.yaml`. Handle false alarms with a `.gitguardian.yaml` ignore entry reviewed in the PR, or by ignoring the incident in the GitGuardian dashboard. On pull requests, dependency review fails if a change adds a dependency with a known vulnerability of any severity.

`.github/workflows/codeql.yml` runs CodeQL `security-extended` queries for GitHub Actions and JavaScript/TypeScript on pushes to `main`, on pull requests, and weekly. `.github/dependabot.yml` opens update pull requests for npm, Docker, and pinned GitHub Actions. Every action is pinned to a commit SHA.
