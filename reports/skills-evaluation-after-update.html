Verdict

The first update pass is valid and improves the skill system in the right order. The stale Obsidian and Draw.io references are fixed, and six high-use skills now have baseline eval fixtures. The remaining risk is mostly architectural: many skills still load too much detail directly in SKILL.md, and several descriptions are too weak to trigger reliably.

Benchmark status: with-skill versus baseline model evals were not run in this pass. The available subagent tool requires an explicit request for delegated/subagent work, so this report covers static evaluation only.

What Passed

  • All six new evals/evals.json files parse as valid JSON.
  • All six new eval files match the required top-level schema and skill folder names.
  • The scan for SecondBrian, render_drawio.js, cd scripts, and node scripts in claude/skills is clean.
  • The core staged-change workflow skills now have 3 eval prompts each: review, security-review, and commit-msg.
  • The core personal-workflow skills now have 3 eval prompts each: search-notes, triage, and todoist-operations.

Highest Priority Issues

  • Descriptions without trigger language: book-review, build-persona, feed-catchup, highlight-graph, now-reading-page, reader-recap, readwise-cli, readwise-mcp, surprise-me, and triage.
  • Oversized skill bodies: book-review, build-persona, cve-writeup, exec-brief, feed-catchup, grill-me, highlight-graph, now-reading-page, reader-recap, readwise-cli, readwise-mcp, surprise-me, and triage.
  • Credential handling concern: readwise-cli still says to ask the user for a Readwise token. That should be changed to prefer existing auth, environment variables, or a local secret manager pattern.
  • Coverage gap: 27 of 33 skills still have no eval fixtures.
