Key Findings

  • Skill authoring guidance says descriptions must include both what the skill does and when to use it, and should be strong enough to trigger reliably.
  • The same guidance says main SKILL.md files should stay small, with deeper workflow details moved into references/.
  • Six high-use skills now have initial evals/evals.json fixtures, giving the cleanup work a measurable baseline.
  • Several Readwise-oriented skills overlap in trigger space and should get clearer boundaries.
  • Command and agent wrappers only partially mirror the skill inventory. That is not automatically wrong, but the intended split should be explicit.
  • OpenSpec is present but not ready for strict proposal workflow because openspec/project.md still has template content and the openspec CLI is not available in this shell.
